# Editorial model and repeatable conversion

The immutable recovered document and the editorial content item are different entities. `src/editorial/model.ts` validates documents, items, contributions, authors, eras, places, themes and reorganization proposals. `src/editorial/content.ts` shares the generated content schema with Astro. The existing `works` collection remains an internal compatibility store; `level` determines canonical `/divergences/`, `/works/` and future `/worlds/` paths. Previously published work slugs remain stable through `data/legacy-edition.json`.

`data/map.yaml` uses JSON syntax, a deliberately restricted subset of YAML 1.2. It has one registry object per line for reviewable diffs, without a second parser dependency. It is build input, never a served asset. Documents retain URL, original path, SHA-256, capture/retrieval provenance and media type. Items reference whole documents or block ranges with an exact digest; a source-byte or fragment change stops conversion. Several documents require explicit `chapters` or `equivalent` composition.

Interpretations contain `value` plus `review: {by, state, reason, quote}`. `unknown` is valid for every classification; empty vocabulary registries remain intentional until S4. Proposed names, language, genre and reply relationships are hypotheses, not owner approvals. Contributions retain source position, attributed voice, original introduction, proposed kind and reply evidence. Reply targets cannot be missing or self-referential. Names are not merged as identities or aliases. Source mail links become plain content, retaining attached portraits; addresses never reach served views.

Regenerate proposals with `pnpm editorial:map`, retain/validate the existing random sample with `pnpm editorial:sample`, then enrich the selected edition with `pnpm editorial:enrich`. Regeneration preserves owner decisions, including field-level language/classification and reviewed contributions; changed owner-reviewed source hashes require explicit reconciliation. The S3 development-only review interface is still to build. Do not hand-edit original files or silently replace the fixed sample when a case fails.

The map proposes splits at original colored prompt titles and anchored collective headings. Its 7,093 divergence prompts and 635 anchored pieces are candidates for progressive review, not declarations of final editorial boundaries. Only explicitly numbered, contiguous parts with the same stated author and a continuation link are automatically proposed as a chapter merge. S2 exercises this with the five parts of L'Impero Pontico. The two 25 July 1943 texts remain separate: similar filenames are insufficient evidence.

`pnpm convert` publishes the fixed 30-item sample, existing trials and the explicit merge: 43 canonical items and three compatible source previews. Cleaned HTML preserves tables and formatting where Markdown is insufficient. Paragraph-level parsing preserves wrapper anchors, contribution introductions and image signatures; Markdown escapes literal angle-bracket transcriptions. Source labels and stories keep their language, while generated navigation and image fallback descriptions follow IT/EN.

PDF preparation independently extracts the text layer and raster illustrations with `unpdf` and encodes illustrations as safe PNGs with Sharp. Illustrations precede the text on their original page; this is a reading edition rather than a geometric replica. OCR, vector-only illustrations and arbitrary complex PDF layouts are not covered. The seven-page Sardinia trial retains all three raster images and its English final letter, with raw text independently compared. Wrapped year ranges remain one timeline label.

Corrections live in `data/corrections/<slug>.json`; see that directory's README. Every unresolved link has a stable entry and reason in `reports/link-gaps.json`, rendered in both language versions of `/gaps/`. Recovered-but-unpublished documents are distinguished from archive gaps, excluded external resources and unsupported attachments. `pnpm links:check` verifies generated targets and anchors, privacy and CSP compatibility. Its per-target cache avoids repeatedly parsing the gap register.

`pnpm build` validates the schema, reconstructs content, checks types and links, then compares every published text against its selected source blocks. `reports/sample-comparison.json` records exact normalized text, declared removals, source anchors, tables, headings, image hashes/order and attributions. `reports/s2-validation.json` records the fixed random subset; browser evidence is recorded separately in `reports/s2-browser.json`. Neither automated source fidelity nor this first browser pass is a full editorial review or the S6 accessibility audit.
